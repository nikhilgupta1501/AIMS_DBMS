Relational Schema Architecture & Normalization Proof

Formal documentation of 3NF design, referential integrity safeguards, triggers, and stored procedures.

1. Conceptual Entities & Relational Representation

The system is modeled across 11 relational entities ensuring single source of truth and referential integrity:

USERS (user_id [PK], full_name, email [UK], password_hash, role, created_at) CATEGORIES (category_id [PK], category_name [UK], description, created_at) SUPPLIERS (supplier_id [PK], company_name, contact_person, email [UK], phone, address, lead_time_days) PRODUCTS (product_id [PK], sku [UK], product_name, category_id [FK], unit_price, cost_price, reorder_threshold, lead_time_days) WAREHOUSES (warehouse_id [PK], warehouse_name, location, code, max_capacity) WAREHOUSE_STOCK (stock_id [PK], warehouse_id [FK], product_id [FK], quantity_on_hand, last_updated, UNIQUE(warehouse_id, product_id)) PURCHASE_ORDERS (order_id [PK], supplier_id [FK], created_by_user_id [FK], order_status, total_amount, order_date) PURCHASE_ORDER_ITEMS (order_item_id [PK], order_id [FK], product_id [FK], quantity_ordered, unit_cost, line_total) STOCK_TRANSACTIONS (transaction_id [PK], product_id [FK], warehouse_id [FK], performed_by_user_id [FK], transaction_type, quantity_change, balance_after, notes) STOCK_ALERTS (alert_id [PK], product_id [FK], warehouse_id [FK], current_quantity, reorder_threshold, alert_severity, alert_status) FORECAST_LOGS (forecast_id [PK], product_id [FK], model_name, forecast_period, predicted_demand, actual_demand, confidence_score)

2. Third Normal Form (3NF) Normalization Breakdown

  • 1NF (Atomicity): Every attribute holds atomic, indivisible values. Tables have uniquely identifiable primary keys. Multi-valued repeating groups (e.g. order items) are extracted into independent relations.
  • 2NF (No Partial Dependencies): For composite keys like (warehouse_id, product_id) in WAREHOUSE_STOCK, only inventory quantity depends on the composite pair. Product metadata is maintained strictly in PRODUCTS.
  • 3NF (No Transitive Dependencies): Eliminated all functional dependencies of the form $X \rightarrow Y$ where $X$ is not a superkey. For instance, category descriptions do not sit on PRODUCTS; they are normalized into CATEGORIES. Supplier contact details sit in SUPPLIERS, not on PURCHASE_ORDERS.

3. Constraints, Triggers & Stored Procedures

Constraint / Object Type Target Relation Enforcement Semantics
chk_non_negative_stock CHECK Constraint warehouse_stock Guarantees quantity_on_hand ≥ 0. Prevents physical inventory balance from ever going negative.
chk_user_role CHECK Constraint users Restricts authorization role values to ('ADMIN', 'STAFF', 'MANAGER').
trg_stock_level_alert Trigger (AFTER UPDATE) warehouse_stock Fires when quantity changes. Inserts alert into stock_alerts if quantity drops below threshold; auto-resolves when restocked.
sp_process_stock_movement Stored Procedure Cross-Table Executes atomic inventory updates, validates foreign keys, checks stock sufficiency, and logs immutable transaction audit.
v_monthly_sales_velocity SQL View stock_transactions Aggregates historical monthly sales volume per SKU, feeding the Python machine learning training pipeline.
